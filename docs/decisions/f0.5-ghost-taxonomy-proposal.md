## What this gate decides

The 13 ghost occurrences are recipe `allowed_patterns` ids absent from `pattern-manifest`.
Each must be classed as **pattern** (a section/UI block in the manifest taxonomy:
conversion/layout/motion/ux/data/logic_pattern), **direction** (an art/theme direction —
NOT currently a first-class type; would be introduced by F1 `direction_ids`), or **asset**
(a concrete reusable asset: mascot, motion effect, background).

**Two structural decisions drive F1's schema and must be settled first:**

- **D1 — Is "direction" a first-class type?** `theme-crossed-direction` already exists as a
  `layout_pattern`. The ghosts `theme-crossed-motion` and `theme-crossed-positioning` are its
  motion/positioning treatments. Either (a) introduce a real `direction` concept (F1 adds
  `direction_ids`), or (b) collapse them into the existing pattern with modifiers (no new type).
- **D2 — Split asset from pattern?** `cat-concierge-guide` conflates a specific mascot *asset*
  ("cat concierge") with a *pattern* (guided mascot, ≈ existing `mascot-progressive-guide`).
  Either split into `asset_id` + `pattern_id`, or keep as one pattern.

# Decisions recorded (2026-06-22, owner sign-off)

## Structural (gate F1 schema)

- **D1 = COLLAPSE.** `theme-crossed-motion` (A2) and `theme-crossed-positioning` (B1) collapse into
  the existing `theme-crossed-direction` pattern with a modifier (motion / positioning). **No new
  `direction` type; F1 does NOT add `direction_ids`** → smaller F1 schema. (Owner)
- **D2 = SPLIT.** `cat-concierge-guide` (A3) → asset `cat-concierge` (mascot) + pattern
  `mascot-progressive-guide` (existing). F1 asset/pattern ref split applies. (Owner)

## A6 / A7 — decided via real Codex+Opus brainstorm (owner-delegated judgment)

Codex (tech-opponent) split them on the principle **PATTERN = behavior/layout contract; ASSET =
concrete instantiated material (has media payload + source/license)**. Opus concurred.

- **A6 `mask-reveal` → PATTERN** (`motion_pattern`, marked **effect/modifier** — NOT a standalone
  section). A reveal technique has no media payload/provenance; asset.schema would force an empty
  source/license (smell) and lose the content-purpose + reduced-motion contract. Consistent with D1,
  we do **not** add a new "effect" type for one value — register as `motion_pattern` whose `requires`
  enforces content purpose + reduced-motion fallback; introduce an effect subkind only if more appear.
- **A7 `motion-background` → ASSET** (background). Concrete backdrop with a payload; asset.schema
  already models backgrounds and carries the floors (motion_level, performance_cost, mobile_safe,
  license, source, avoid_with). As a pattern it would bypass asset-level provenance/blocking.
